# 中英雙語規則

## 雙語一致性檢查

**中英混排格式**：逐字元規則（中英之間加空格、CJK 相鄰的半形標點改全形、破折號）由門禁指令碼 `check_punctuation.py` 檢測，見下文「標點規則」。本節只保留指令碼不判斷的：術語跨全文一致。

**中文裡的英文**：標記出現的未翻譯英文，建議翻譯或加說明。

**雙語對**：確認 EN 和 CN 版本傳達的意思相同；標記翻譯損失。

## 英文術語首次出現規則

- 首次出現：保留英文 + 中文註解，或中文前置 + 英文括注（`指令微調（Instruction tuning）`）
- 後續出現：只用中文，不要英中混用
- 例外：SFT、RL、MoE 這類已成行業通用縮寫，全程保留縮寫形式

## 有穩定中文對譯的英文詞

中文技術圈已有通用譯法的，換中文：

| 英文 | 推薦中文 |
|------|----------|
| context | 上下文 |
| state | 狀態 |
| cache | 快取 |
| claim | 斷言 |
| runtime | 執行時 |
| contract | 契約 |

術語在中文圈還未收斂的（prompt、embedding、tokenizer），保留英文合理。

## 翻譯腔套路（主動排查）

**物理動作動詞**：接住、擊穿、鋒利、不崩、不爆、打穿、扛住，這類詞把抽象認知過程想像成了物理動作（骨架是英文 catch/pierce/sharp）。換成日常中文：你這幾條我都收到了 / 這個假設不成立。

**形容詞預判+冒號**："更乾淨："、"邏輯很清晰："引出內容。刪掉形容詞，只留後面事實。

**抽象名詞做主語**："工程上的現實比這些數字難看"這種骨架，凡碰到"X 的 Y 比 Z 更 W"，重寫讓人/動作做主語。

**有穩定對譯詞直接混入**："context 不崩、state 可恢復"，換成中文。

## 雙語並列的排版

中英雙語 release notes 的排版：

- 英文版在前，中文版在後（或分兩個段落）
- 條目編號一一對應
- 專有名詞（產品名、功能名）在兩種語言裡保持一致
- 不要在同一條內中英混寫

## 標點規則

逐字元標點與中英 / 中西混排由門禁指令碼 `check_punctuation.py` 強制檢測（全形 / 半形、中西空格、破折號），本節只保留需要判斷的部分：

- 中文裡的英文術語首次出現保留英文 + 註解，後續統一中文（指令碼不判斷語義）。
- 引號方向、是否成對需要人工判斷，指令碼不檢測。
